## 一、 背景与产品哲学

### 1.1 现状与行业痛点分析
当前市场主流的新标签页扩展（如 Momentum、Infinity、iTab 等）普遍走向了“重型化、娱乐化、商业化”的歧路：
- **视觉过载**：强制占据屏幕的大幅壁纸、动态天气、名言、3D时钟，不仅分散工作注意力，而且每次新开标签页都会造成 200ms~500ms 的明显渲染白屏与高 CPU/GPU 瞬时消耗。
- **信息噪音**：堆砌新闻流、股票理财卡片、商业化推广返利导航，违背生产力工具初衷。
- **脱离真实工作场景**：
  - **缺乏内网感知**：在企业办公内网、私有云或离线开发环境下，因无法连接外网天气/壁纸服务器而频繁报错或排版崩坏；内网 IP/私有域名（如 `192.168.x.x`、`gitlab.corp`）无法获取 Favicon，导致界面全是灰色破损图标。
  - **搜索强制外网**：默认且无法深度定制外网大厂搜索框，而内网员工日常几乎不用外网公共搜索，需要的是直达内部服务或内网知识库。
  - **割裂历史与当前工作流**：未能与用户的“实际浏览历史、正在进行的任务、书签沉淀、标签生命周期”形成有机联动。

### 1.2 YiTab 的核心设计哲学
> **“零视觉噪音、极速渲染起跳、懂你当前工作流的智能工作台”**  
> *(Clean, Zero-Noise, Sub-50ms Trampoline, Context-Aware Launcher)*

1. **直观与极简 (Intuitive & Minimalist)**：
   - 告别花哨壁纸和鸡汤动效，界面只保留高密度、高可读性的生产力信息。
   - 采用精致的现代轻量排版（统一网格栅格、系统原生字体、低饱和度专业配色，支持原生深色模式）。
2. **极速起跳 (High-Performance Trampoline)**：
   - 首屏渲染控制在 **< 50ms** 以内，无任何外部 CDN 依赖，纯本地持久化优先（Local-First）。
   - 键盘第一公民：全键盘快捷键瞬间直达目标。
3. **双场景深度适配 (Dual-Profile Awareness)**：
   - 完美兼顾 **“企业内网/办公环境”**（内网域名、直接访问、书签平铺、零外网依赖）与 **“个人电脑/混合场景”**（多源搜索、技术社区、论坛与个人常用）。
4. **与 YiTab 标签生态完全打通**：
   - 不仅是个导航页，更是**会话快照恢复大厅、书签快速展开矩阵与多窗口任务管理器**。

## 二、 核心产品命题深度剖析：打开主域名 vs 打开上次完整路由？

用户在需求中提出的核心思考：  
> *“可以结合历史打开的网站，去建议啊，类似猜你想打开，这样的功能，但是这点就涉及到是打开上次的完整路由网站还是说打开主域名，这个你自己分析下……”*

这是一个极具洞察力的命题。在真实的浏览器交互中，**盲目跳转上次完整路径**或**一刀切返回主域名**都会在特定场景下带来糟糕的体验：

### 2.1 典型业务场景冲突矩阵

| 场景类别 | 典型代表网站 | 若跳转“上次完整路径”的体验 | 若跳转“主域名/根目录”的体验 | 用户真实核心意图 |
| :--- | :--- | :--- | :--- | :--- |
| **工作台/门户首页** | GitLab、Jenkins、OA门户、Wiki、数据看板 | **极差**。跳入具体某个已构建完的任务、过期日志或临时页面，用户必须再次手动点击回首页 | **完美**。直接进入仪表盘开始新一天工作 | 90% 想看全局工作台 |
| **具体工单/代码评审** | Jira Issue、GitHub PR、某个正在编写的文档 | **极佳**。帮助用户无缝恢复上下文（Resume Context），不用从首页层层点击翻找 | **较差**。还得重新去搜索或从动态列表中找那个 Issue | 希望继续刚才的工作现场 |
| **社区/资讯/论坛** | V2EX、Reddit、Hacker News、掘金 | **较差**。跳到昨天看过的某篇旧帖子（已读完），无法获取最新资讯动态 | **极佳**。直接浏览最新热榜和动态列表 | 浏览最新动态内容 |
| **单页应用/鉴权系统** | 各类内网系统、云平台控制台 | **灾难**。历史路由带有临时 Token 或 Session 参数，直接访问导致 `401 Unauthorized` 或死循环重定向 | **极佳**。走正常登录重定向或首页入口 | 安全进入系统有效页面 |

### 2.2 解决方案：双态呈现体系 (Primary Domain + Resume Context Capsule)

经过深度对比与推演，YiTab 将采用**“主行动点进入主域名 + 辅助微胶囊恢复上下文”**的双态智能架构，同时配合**路由特征启发式规则**，彻底兼顾两类诉求：

```text
+-----------------------------------------------------------------------+
|  [ 🌐 Jira 任务中心 ]                                    (频次 Top 1)  |
|  jira.corp.internal                                                   |
|                                                                       |
|  主卡片点击 => 打开系统主站首页 (https://jira.corp.internal/)          |
|                                                                       |
|  +-----------------------------------------------------------------+  |
|  | ⏱️ 继续上次: [PROJ-1024 标签去重算法优化与死链排查] ↗             |  |
|  +-----------------------------------------------------------------+  |
|  (点击胶囊 => 恢复具体工单完整路由，悬浮展示添加时间与路径详情)          |
+-----------------------------------------------------------------------+
```

#### 1. 默认主操作：规范化主域名入口 (Primary Entry)
- 点击卡片主体区域：默认打开**网站的核心工作台入口**（协议 + 主机名 + 一级固定前缀，如 `https://github.com`、`https://jira.oa.com`）。
- 绝不因上次看了一个失效报错页面，导致用户后续每次点开都是报错。

#### 2. 上下文恢复微胶囊 (Resume Context Capsule)
- 如果该站点最近一次打开的页面是一个**深层具体内容页**（Deep Content Page），系统会在卡片底部展示一条极轻量的**“继续上次：[标题缩略]”**胶囊按钮。
- 用户想看最新总览就点卡片，想继续昨天的任务就点胶囊，**一击即达，拥有完全自由的掌控权**。

#### 3. 路由智能启发式判别算法 (Route Intelligence Heuristics)
通过自动分析 URL 的深度与语义特征，动态决定是否呈现“继续上次”胶囊，以及胶囊的具体目标：
- **判定为“无需恢复”的浅路径/无状态页面（直接仅显示主站）**：
  - 路径等于 `/`、`/home`、`/index.html`、`/dashboard`、`/welcome`、`/feed`。
  - 仅包含纯营销追踪参数或空参数的页面。
- **判定为“高价值工作上下文”的深层页面（自动提取并呈现胶囊）**：
  - 符合工单/代码/文档特征模式：`/(issues|pull|merge_requests|ticket|task|doc|wiki|article|post|p|item)/[\w-]+`。
  - 包含业务内容查询参数：如 `?id=...`、`?issue=...`、`?project=...`。
- **参数脱敏与清洗**：
  - 提取上次路由时，自动剥离敏感或临时参数（如 `token=...`、`t=172899`、`authCode=...`、`utm_*`），确保胶囊链接的持久有效性。

#### 4. 用户专属偏好设定
在设置中提供一键切换选项：
- “卡片主行为偏好”：
  - `选项 A（默认）`：卡片主体打开主站首页，深层内容通过胶囊直达；
  - `选项 B`：卡片主体始终打开最后访问的完整网址；
- 用户还可在任意卡片上右键定制该站点的独立行为。

### 3.1 核心模块一：多场景工作模式切换 (Work vs Home Profiles)
针对用户在“办公内网”与“个人电脑”下的截然不同行为习惯，提供双环境模式：

1. **办公模式 (Work / Intranet Profile)**：
   - **特点**：隐藏外网公网搜索引擎；突出内网 IP、公司域名直达、局域网工具导航与工作书签。
   - **自动识别感知**：可配置“自动识别规则”（当当前处于 `192.168.*`、`10.*`、特定企业域名后缀或私有网段时，自动无感激活办公模式）。
   - **内网 Favicon 自愈机制**：对于内网没有标准 favicon.ico 或因防火墙拦截的系统，系统自动基于站点名称生成**高辨识度双色渐变矢量首字母图标（SVG Icon Generator）**，彻底避免破损图片。

2. **个人生活模式 (Home / Personal Profile)**：
   - **特点**：启用聚合搜索引擎切换（Google、Baidu、Bing、GitHub、知乎、Twitter/X）；展示论坛、影音、日常技术学习与个人书签。

3. **快捷切换**：
   - 顶部右上角常驻极简切换按键，一秒即可手动平滑切换，数据按 profile 分别存储，互不干扰污染。

### 3.2 核心模块二：猜你想开 · 智能推选引擎 (RFT 推荐模型)
不采用简单的“按总打开次数排序”（传统浏览器新标签页的弊端是半年前高频访问、如今早已不用的网站长期霸屏）。  
YiTab 采用轻量且精准的 **RFT（Recency, Frequency, Time-of-Day）自适应衰减推荐算法**：

1. **时间衰减计算 (Recency Decay)**：
   - 越近期打开的权重越高，采用半衰期递减模型（如 7 天半衰期），新产生的常用工作站能在 2 天内快速置顶，老旧停用项目自动淡出。
2. **时段感知分析 (Time-of-Day Context)**：
   - **早间时段 (08:30 - 10:30)**：推选每日晨会待办、考勤系统、Jira/禅道看板、未读邮件。
   - **下午专注时段 (13:30 - 18:30)**：推选开发环境控制台、Git 仓库、代码评审、API 调试平台。
   - **晚间与休息日**：推选技术博客、技术社区、影音论坛。
3. **已开标签感知**：
   - 若某推荐站点当前已经在其他窗口打开，卡片上直接打上“已打开 · 点击聚焦”的小角标，点击后直接激活已有标签，与 YiTab 核心防重复拦截思想完美呼应！

### 3.3 核心模块三：极简全能聚合搜索条 (Omni-Search Launcher)
- **纯内网直接直达**：输入内网 IP（如 `192.168.1.100:8080`）或本地开发端口（如 `:3000`、`localhost:5173`），回车直接打开，不经过任何多余搜索跳转。
- **快捷键前缀切换引擎**：
  - 输入 `g react docs` => 触发 Google 搜索
  - 输入 `b 架构设计` => 触发 百度 搜索
  - 输入 `gh yitab` => 触发 GitHub 仓库搜索
  - 输入 `w confluence` => 触发 内部 Wiki 搜索
  - 按 <kbd>Tab</kbd> 或键盘左右箭头在引擎之间无缝切换。
- **集成全局统一索引**：键入关键字时，下拉无刷出当前窗口标签、收藏夹书签及历史记录，体验与已实现的 <kbd>Alt+K</kbd> 命令面板完全一致，零学习成本。

### 3.4 核心模块四：固钉工作台与平铺书签树 (Pinned Matrix & Bookmarks Direct)
- **固钉工作台 (Pinned Matrix)**：
  - 用户可自主固钉任意内网常用后台、业务系统、常用工具。
  - 支持创建逻辑分组（如“DevOps 运维工具”、“微服务中台”、“日常办公”），支持拖拽排序。
- **书签快捷平铺看板 (Bookmarks Direct Matrix)**：
  - 彻底改变“在浏览器顶部小书签栏逐层小心翼翼悬停点开”的局促体验。
  - 在新标签页下方，直接平铺展示用户收藏夹的核心一级/二级目录卡片，以清爽的清单形式陈列。
  - 支持即点即开、支持在看板内对书签关键词毫秒级过滤。

### 3.5 核心模块五：会话沉淀与未完任务恢复 (Session Resume Center)
与 YiTab 现有功能（`会话快照` 与 `闲置标签沉淀`）无缝对接：
- 新标签页底部显示上次关闭的标签页概览：“上次浏览留有 8 个标签页，一键恢复全部 ↗”。
- 展示已保存的最近会话快照，工作流断点续传。

## 四、 页面排版、视觉规范与极简美学

为了满足用户**“不需花哨，直观，简洁明了”**的明确诉求：

### 4.1 视觉原则
1. **背景与呼吸感**：
   - 浅色模式采用温润柔和的纸质纯色灰白调（`#f8fafc`），深色模式采用深邃耐看的高级炭灰（`#0f172a`）。
   - 严禁默认加载高对比度杂乱风景图片或强光壁纸；允许用户纯色微调。
2. **排版网格 (Grid & Rhythm)**：
   - 核心内容区最大宽度约束为 `1200px`，居中排列，适配不同尺寸的办公显示器与笔记本。
   - 卡片采用微圆角（`8px`~`10px`）、`1px` 极细边界线（`#e2e8f0`）与微投影，信息层级分明。
3. **内网站点图标生成器 (Intranet SVG Favicon Generator)**：
   - 针对内网或没有 Favicon 的站点，自动通过站点域名/标题计算哈希，生成配色优雅的带首字母 SVG 徽标（如 Jenkins 蓝红白徽标、GitLab 橙紫徽标风格）。绝不留破图红叉。
4. **全键盘可访问性 (Keyboard Accessibility)**：
   - 新标签页打开后焦点默认自动定位于搜索条，直接输入即可直达。
   - 按下方向键 <kbd>↓</kbd> 立即将光标落入“猜你想开”卡片阵列，全键盘无鼠标游走操作。

## 五、 技术实现架构与工程可行性

### 5.1 WXT 扩展接入架构
在 WXT 中，接管 Chrome 新标签页只需在工程中创建 `src/entrypoints/newtab/` 目录结构：

```text
src/entrypoints/newtab/
├── index.html               # 新标签页入口 HTML
├── main.tsx                 # React 18 入口组件
└── style.css                # 极简全局样式与重置
```

WXT 会在编译时自动在 Manifest 中生成配置：
```json
{
  "chrome_url_overrides": {
    "newtab": "newtab.html"
  }
}
```

### 5.2 权限需求与评估
当前项目 `wxt.config.ts` 已拥有完整所需权限，无需新增敏感权限：
- `history`：已具备，用于本地分析访问频次与时段统计。
- `bookmarks`：已具备，用于平铺展开书签分类目录。
- `tabs`：已具备，用于判定推荐站点是否已有已开标签，并实现点击直接聚焦跳转。
- `storage`：已具备，用于持久化固钉卡片、场景分组与用户偏好。

### 5.3 纯本地计算与隐私安全承诺 (100% Local Privacy)
- 历史行为、时段特征分析、书签解析**全部在浏览器本地沙箱内实时计算完成**。
- **零外部网络通信，零埋点追踪，代码开源透明**，即使处于完全断网的军工/金融离线专网环境中，也能 100% 正常稳定运行。

## 六、 阶段迭代路线图与开发规划

### 阶段 5.1：新标签页基础骨架与直达工作台 (v1.1.0)

- [ ] 顶部多模式搜索直达条：支持内网 IP/端口直接直达、Google/Baidu 多引擎切换。

## 七、 总结与评审建议

本方案紧密贴合用户在**“内网直达、直观简洁、不需花哨、智能猜你想开、兼顾个人日常”**上的核心述求，并通过**“双态架构（主站直达 + 继续上下文胶囊）”**从算法与交互层面完美破解了“跳转主域名还是上次深层路由”的痛点选择题。
